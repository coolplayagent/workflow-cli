# 流程定义 IR v1

本章定义 R01 静态语义。[定义注册表](definition-registry.md)提供带 revision 的编辑和不可变发布；
[内核](kernel-semantics.md)提供 bundle 检查、确定性控制流和检查点回放；
[RunStore](run-store.md)持久化这些变更，外部执行与权限仍由宿主负责。

## 表示与标识

JSON、YAML 和 `WorkflowBuilder` 产生相同的 `Workflow` 结构。未知字段、重复结构字段、不支持的
schema 版本和尾随文档都会被拒绝。CLI 文档最多 1 MiB，图最多 4096 个节点、16384 条边。
稳定 ID 长度为 1–128，只允许 ASCII 字母、数字、`_`、`-`、`.`；节点和边分别在各自命名空间内唯一。

版本是不透明的不可变发布 ID，字符集与稳定 ID 相同。范围、`latest`、`head`、`main`、`master`、
`stable`、`x` 均被拒绝。这只是语法检查；注册表还必须解析准确引用，并验证内容与能力契约。
语法上固定的版本不能证明内容不可变或资源可用。编译器不执行或解析策略、能力与子流程引用。

规范 JSON 按 ID 排序节点，按类型结构声明顺序输出字段，排序 map 键；边顺序保留，因为 first-match
决策依赖它。摘要是 `sha256:` 加这些 UTF-8 字节的 SHA-256。这是 workflow-v1 规范形式，并非
RFC 8785。流程 ID、版本、契约和字面值都参与摘要；导入/导出保留稳定 ID 与行为，无关空白变化
不改变摘要。注册表在把摘要视为发布版本前冻结校验通过的内容。API 分别暴露规范化与校验；
CLI 只在校验成功后输出摘要。

## 类型与数据交接

契约把字段名映射到值类型和 `required` 标志。类型包括字符串、布尔、整数、数字、同类数组与封闭对象。
嵌套对象的字段全部必填；顶层可选字段允许缺失。Null 不属于任何类型。整数可流向数字，数组和对象
递归检查兼容性，不会把数字字符串强制转换成数值。

节点输入绑定选择流程输入、先前节点输出或类型化字面值。未知输入/输出、缺少必需绑定、可选值绑定到
必填字段、自身或未来节点依赖，以及类型不兼容都导致静态校验失败。图的祖先关系只说明可能的先后
顺序，不代表节点一定执行：跳过分支的输出仍可能不可用。执行层必须检查真实输入是否存在，不能用
null 或伪造成功替代。

`validate_values` 独立校验真实值，拒绝未声明字段、缺少必填值和错误类型。前置条件读取节点输入；
决策条件也读取输入，把先前输出绑定为输入才能明确交接。任务与等待结果使用声明的输出契约。
内核检查子流程/循环的返回契约，其他控制节点输出必须为空。成功终点的输入成为流程返回值。

## 图结构与路由

外层图必须无环、所有节点可从入口到达，并且每个节点都有通向明确终点的路径。这是保守的结构检查，
不能证明任意业务条件都会终止。每条边都有 ID 和路由。多个入边要求目标是 join 或 terminal；
内核先处理边 token、校验封闭分支区域，再取消未获选分支。

| 节点 | 静态契约 |
| --- | --- |
| `task` | 固定版本的能力及可选策略；恰好一条 `next` 边 |
| `subworkflow` | 固定版本的流程；恰好一条 `next` 边 |
| `decision` | 至少一个 `case`，恰好一个 `otherwise`；明确声明模式 |
| `fork` | 至少两条 `next` 边，目标不同 |
| `join` | 至少两个入边，一条 `next`；明确声明模式和剩余分支策略 |
| `wait` | 正超时和事件 ID；出口必须为 `accepted`、`rejected`、`timed_out` |
| `loop` | 固定版本的循环体、正迭代上限和截止时间；出口为 `completed`、`exhausted` |
| `terminal` | `succeeded`、`failed` 或 `cancelled`；无出边 |

循环调用独立版本的流程体。每轮分配新的节点实例，所有轮次锁定同一循环体；成功时结束，失败轮次
只在迭代次数与总截止时间的双重限制内重试。逻辑截止时间覆盖整个循环，并在检查点回放中保留。
耗尽后先完成子节点取消，再走强制的 exhausted 出口。隐式图回边和 bundle 内递归的子流程/循环依赖
都被拒绝。

## 已实现的条件求值

相等与不等使用结构化 JSON 相等，不进行类型转换；整数 `1` 与浮点表示 `1.0` 不同。
`exists` 对缺失输入返回 false；直接比较缺失值报错。`all` 和 `any` 至少需要一个操作数，并从左到右
短路求值，所以可以先用 `exists` 保护随后对可选字段的比较。`not` 对一个条件取反。

选择分支前先按节点契约检查提供的值，随后按声明的边顺序计算 case 表达式，条件错误会使选择失败。
`exclusive` 模式下多个条件为真是错误；`first_match` 选择第一个真值条件；没有匹配则选 `otherwise`。
即使存在匹配 case，格式错误的路由仍被拒绝。前置条件必须是有效表达式；false 使节点跳过，错误使节点失败。

## 内核运行语义

跳过分支不等于成功工作。`all` join 等待所有入边 token，失败或取消会阻止成功；至少有一个成功分支时，
跳过 token 为中性；全部跳过则 join 跳过。`any` 按确定性 token 顺序选择第一个成功结果。
`cancel_and_reconcile` 对经过验证的封闭 fork 区域请求取消，不确定结果需要明确核对事件；`await`
记录剩余结果。只有所有节点、包括未获选节点都结束后，frame 才完成。没有成功分支时 join 不能成功。

等待消费、终点仲裁、数据可用性和事件顺序详见[内核语义](kernel-semantics.md)。单元测试与 CLI 回放
覆盖这些变更；RunStore 测试持久化等待与截止时间；真实 HTTPS 执行比较 scheduler 丢失后的本地和远程
业务状态。外部取消与提供方核对有各自运行时验收，见 [R01 验收](definition-acceptance.md)。

## 诊断

静态诊断包含 `code`、`file`、`path`、可选 `node`/`edge` ID 和原因。解析错误尽可能保留解析器位置
与嵌套字段路径，不需要模型解释就能判断校验是否通过。校验器不依赖文件、时钟、传输或提供方。
CLI 与 HTTPS `validate_definition` 共用 `validate_source` 和 `ValidationReport`；真实 HTTPS/PostgreSQL
矩阵比较包含字段路径和 ID 的完整报告。报告限制诊断数量与编码字节数，同时不会接受无效输入。
详见[校验边界与可复现证据](definition-acceptance.md)。
