# 如何阅读本书

业务流程经常从一张清单开始：检查变更、请求操作员批准，只在检查结果仍然有效时发布。
Agent 可以协助完成各步，但清单本身不能说明崩溃前已经执行了什么、批准的是哪个版本，
或者迟到的 worker 结果是否仍然有权提交。Workflow CLI 将这些问题变成明确的执行契约。

本书以审批流程为贯穿示例。你会先在本地执行它，再理解流程定义、worker 结果与证据之间的
关系，随后把相同契约扩展到外部操作和共享执行。最后一篇介绍如何复现验收证据和排查运行。

## 四种职责

| 组件 | 职责 | 需要检查的内容 |
| --- | --- | --- |
| 流程定义 | 声明合法步骤、数据交接、决策和终态 | 版本、摘要、契约及明确的资源上限 |
| Skill | 帮助 agent 选择 CLI 操作，按需读取指引 | 任务参考和本地手册 |
| 模型与能力适配器 | 提出有界决策或执行实际工作 | 允许的工具、宿主绑定、请求与结果 |
| 持久化运行时 | 接纳状态变更，保留所有权、历史和证据 | 运行状态、租约、已提交结果和产物 |

有效的定义描述流程；完成的 CLI 命令说明某项操作已经结束；业务运行成功还要求达到声明的
成功终态并满足强制证据门禁。始终区分这三件事，是本书反复练习的基本习惯。

## 选择阅读路线

首次使用先完成[安装](02-skill-distribution.md)和[第一个工作流](03-getting-started.md)，
无需模型账号或远程数据库。流程作者随后阅读定义和控制流章节；运维人员在修改真实运行前，
先阅读本地执行、后置条件、备份和迁移。接入者在开放服务或接受远程结果前，需要理解 worker
契约和共享执行篇。

验收章节记录有界实验、支持环境和已知限制，可以帮助评估部署，但不能替任意第三方适配器
背书，也不代表生产恢复 SLA。[交付路线图](../06-acceptance-and-maintenance/08-roadmap.md)区分已实现的契约与尚待完成的业务价值评估。

## 在正确的环境中使用示例

发布包用户通过安装目录的 `scripts/workflow.sh` 调用 `workflow`。示例与 schema 分别位于
`assets/examples/`、`assets/schemas/`，完整双语书籍位于 `references/manuals/`。
这些都是本地文件，无需打开 GitHub 即可阅读。

以 `cargo`、`bazel` 或仓库相对路径 `examples/` 开头的维护者示例假设存在源码仓库及固定工具链。
在已安装 skill 中运行 CLI 示例时，应调用包装脚本，并传入 `assets/examples/` 下对应文件的绝对路径。
构建命令和集成测试仍需要其章节列出的编译器、PostgreSQL 或适配器。运行数据库、凭据和工作区应
放在 skill 安装目录之外。

## 每章的检查点

完成入门后，在每次练习中回答三个问题：使用了哪些不可变输入？哪项持久化观察证明已经推进？
如果调用方在收到回复前消失，会发生什么？这些答案把编写、执行和恢复三部分连接起来。
